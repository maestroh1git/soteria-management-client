# One School Day: the Soteria product film

A 60-second, 1080p60 film for proprietors. It follows one pupil's day
through every seat in the school: educator, registrar, front desk, bursar,
parent and staff. It ends on the proprietor's dashboard and **Book a demo**.

Every frame is code. The app screens are rebuilt in HTML at the client's real
size (1440×900 desktop, 390-wide phone), matched against screenshots of the
running client: the same sidebar, icons (lucide), colours, labels and flows.
A small deterministic engine animates them, headless Chromium renders them
frame by frame and ffmpeg encodes the result. The soundtrack is synthesised in
Python from the same timeline, so cuts and text slams land on the beat
(120 BPM).

## Make the film

```bash
pip install numpy scipy imageio-ffmpeg     # imageio-ffmpeg only if ffmpeg isn't installed
npm i -g playwright                        # or have it in node_modules

python3 video/music.py                     # → video/out/soundtrack.wav   (~5s)
node video/render.mjs                      # → video/out/soteria-one-school-day.mp4   (~5 min)
```

Useful while editing:

```bash
node video/render.mjs --preview            # http://localhost:4173, scrub and play with sound
node video/render.mjs --stills 9,18.5,34   # PNGs of single moments
node video/render.mjs --from 30 --to 40    # render just one scene
```

## Change it

Almost everything lives in **`film.json`**:

| To change… | Edit |
|---|---|
| Film colours | `theme`: `stage`/`ink` for the background and captions, `cta` for the button. The app screens keep the app's own colours on purpose. |
| Words on screen | `scenes[].captions`, keeping `at` on multiples of 0.5s to stay on the beat |
| School, pupil, amounts | `story` |
| Tagline, CTA, URL | `brand`. Set `ctaUrl` to show a URL under the button. |
| Scene timing | `scenes[].start` / `end`. The soundtrack follows automatically; re-run `music.py`. |

The screens are in `scenes.js` (one builder per scene). `app.css` holds the
app's look, with a note on where each value came from, and `film.css` holds
everything around the screens. `engine.js` has the animation helpers, and
`icons.js` the lucide icons the app uses, generated by `reference/icons.cjs`.

## Check it against the real app

`reference/` renders the actual client with the same story, so you can compare
the film with the product side by side after a UI change. No API or database
is needed: a fixture API answers the client's requests.

```bash
NEXT_PUBLIC_API_URL=http://api.mock/api npx next dev -p 3001   # the real client
node video/reference/capture.mjs                                 # → video/out/reference/*.png
```

When a screen changes in the app, update its builder in `scenes.js` to match.

## Accuracy rules

The film shows only what the product does today:

- **Parents don't pay online.** Online payment is not live, so the parent
  *opens* the bill and the bursar *records* the bank transfer in Receipts.
  There is no "Pay now" button.
- **Nothing is sent by SMS or email.** Each invoice PDF carries its own link,
  and the film shows the school sharing that PDF with the parent, as schools
  do today.
- The register starts everyone present, and an absence needs a reason before
  it can be submitted.
- At the gate, choosing a barred adult turns the button into a red "Release
  to …" override, as the real screen does.
- Fee payments and payroll post to the same ledger.

All names, numbers and the school are fictional.
